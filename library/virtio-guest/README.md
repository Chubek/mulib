# virtio-guest

MuLIB VMM's **frontend**. Each supported device has its own `.c` file exposing a
device-checked `mulib_virtio_guest_<name>_request()` entry point. These accept
native wire messages and leave device-specific statuses in the response.
Additional convenience functions handle block I/O, entropy, GPIO, I2C, PMEM,
SPI transfers, CAN controller start/stop and RTC clock reads.

`virtio-guest.c` contains shared transport, DMA and stream operations.
[`include/mulib-virtio-guest.h`](../../include/mulib-virtio-guest.h) preserves
single-header use, generated by `python3 tools/amalgamate_virtio.py`.

Link CMake target `mulib_virtio_guest`, or use the implementation switches from
[the manual](../../manual/mulib-virtio-guest.md). Supply a synchronous transport
adapter and guest-addressed workspace. The executable
[`virtio-guest` example](../../examples/modules/virtio-guest.c) connects both sides.

The [protocol and support matrix](../../MULIB_VMMPROTO.md) are shared with the
backend. This library does not yet provide a native kernel/hypercall binding.
