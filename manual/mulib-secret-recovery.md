# Secret recovery

The raw Shamir format does not authenticate shares, threshold or set membership. Keep shares confidential and authenticate metadata and the recovered root independently. This is not an interoperable wallet or backup format. See [secret kernels](secret-kernels.md).

## Source and build reference

[Manual index](index.md) · [Integration guide](integration.md)

| Resource | Location |
| --- | --- |
| Header | [`include/mulib-secret-recovery.h`](../include/mulib-secret-recovery.h) |
| Implementation switch | `MULIB_IMPL_SECRET_RECOVERY` |
| Repository-local includes | [mulib-secret-crypto](mulib-secret-crypto.md) |
| Complete example | [`examples/mulib-secret-kernels.c`](../examples/mulib-secret-kernels.c) |

The include list includes conditional and implementation-only includes;
it is not a minimal link recipe. Use the example (and any setup header it
includes) for a complete switch configuration. See the integration guide
for dependency placement and platform-specific linking.

Compile the example from the repository root on Linux:

```sh
cc -std=c11 -Wall -Wextra -Wpedantic -Werror -UNDEBUG -Iinclude examples/mulib-secret-kernels.c -pthread -lm -ldl -o mulib-example
```
