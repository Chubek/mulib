BODY:
Opaque `mulib_elvi_script_cookies_t`. `mulib_elvi_script_cookies_t *mulib_elvi_script_cookies_load(const mulib_elvi_scrape_program_t *program, const char *requested_path, const char *approved_path)` requires an exact match between the already-resolved DSL path and separately authorized absolute host path; fails closed on POSIX file policy or JSON error. Never use the program stage path itself as the source of approval. POSIX path load requires `_POSIX_C_SOURCE=200809L` (or `_GNU_SOURCE`) before system headers; unsupported builds reject calls to load.
`mulib_elvi_script_cookies_t *mulib_elvi_script_cookies_parse(const mulib_elvi_scrape_program_t *program, const char *json, size_t length)` accepts already-authorized host bytes for that exact profile host; `void mulib_elvi_script_cookies_destroy(mulib_elvi_script_cookies_t *)` wipes then frees and is NULL-safe. Both loaders return NULL on any failure, an empty store for `[]`.
`mulib_elvi_script_transport_t` contains `const mulib_elvi_scrape_program_t *program`, `const mulib_elvi_scrape_https_t *https`, `const mulib_elvi_script_cookies_t *cookies`; all borrowed, cookies may be NULL for no credentials. `int mulib_elvi_script_fetch_https(void *, const mulib_elvi_script_request_t *, mulib_elvi_script_response_t *)` leaves an empty caller-owned output unchanged on failure, transfers a typed response via `message` + `effective_url` on success. Requires trusted blocking TLS connect/peer ops; no redirects or alternate sites. TLS backend is responsible for DNS/destination checks and finite I/O deadlines.
Cookie array wire schema: each object requires `name`, `value`, `domain`, `path`, `secure`, `sameSite` (`Strict`, `Lax`, `None`); optional `hostOnly` (default true), `expires` (null/omitted for session or integral UTC Unix seconds). If you need a pending integration fixture, `[{"name":"session","value":"fixture","domain":"example.org","path":"/","secure":true,"sameSite":"Strict"}]`. SameSite is evaluated in the fixed first-party profile-home context; no foreign-site redirect/replay or Set-Cookie mutation.
Focused test file will be `tests/test-elvi-script-transport.c`; transport manual will be `manual/elvi-script-transport.md`. Verified HTTPS assertions reuse a requested shared W1 helper if accepted; no compile-time dependency on that helper otherwise.
