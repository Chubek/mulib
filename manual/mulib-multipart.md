# Multipart/form-data

[MuLIB repository](https://github.com/Chubek/mulib)

## Scope

Binary-safe multipart/form-data encoding and bounded, length-aware part parsing,
plus the original caller-buffer text-field formatter.

## Integration

Define `MULIB_IMPL_MULTIPART` and `MULIB_IMPL_STRBUF` in exactly one C11
translation unit. Use `#include "mulib-multipart.h"`. Other translation units
include declarations only. No dependency implementations are enabled implicitly.

## Build and test

```sh
cc -std=c11 -Wall -Wextra -Werror -pedantic -Iinclude tests/test-multipart.c -o /tmp/test-multipart
/tmp/test-multipart

```

## API

```c
/* Format single text field into caller buffer; returns byte length or 0 on error. */
size_t mulib_multipart_field(const char *boundary,const char *name,const char *value,char *out,size_t cap);
```

## Safety and ownership

Formats one text field ending with CRLF, not the final `--boundary--` delimiter. Boundary must contain 1..70 ASCII alphanumeric, hyphen or underscore bytes. Name must be nonempty without controls, quotes or backslashes. Values are NUL-terminated strings, not binary payloads; boundary delimiter line prefixes in values are rejected. The caller supplies a suitable boundary and appends the closing delimiter. Returns byte count excluding NUL, or 0 on invalid/capacity/formatting error without writing output. Capacity includes NUL; no overlap. This does not encode filenames or files.

## Binary parts

`mulib_multipart_encode(boundary, parts, count, limit, &bytes, &length)` formats
a complete body including the closing delimiter. Each borrowed part has `name`,
optional `filename`/`content_type`, binary `data` and explicit `length`. Repeated
names are allowed. Metadata rejects controls, quotes and backslashes. Boundary
delimiter collisions in payloads are rejected; choose another boundary and retry.
Zero limit selects 16 MiB. Results are 1 success, -1 invalid input/collision,
-2 limit, -3 allocation. Output is malloc-owned and unchanged on failure.

`mulib_multipart_next(boundary, bytes, length, metadata_limit, &cursor, &part)`
iterates a complete body without copying payloads. Initialize cursor=0. It returns
1 for a part, 0 for the final delimiter, or a negative error as above. On 1 the
part owns its `name`, `filename` and `content_type`, while `data` borrows the body.
Call `mulib_multipart_part_free` before reusing it. Error leaves cursor/output
unchanged. Zero metadata limit selects 32 KiB per part; the caller bounds the
whole input body (OpenAI uses the HTTP body limit).

This parser accepts the strict CRLF form-data profile generated by the encoder:
quoted name/filename, ASCII alphanumeric/hyphen/underscore boundaries of 1..70
bytes, no preamble/epilogue or nested MIME decoding. Unknown MIME headers and
disposition parameters are ignored; escaped quoted-string metadata and extended
filename encodings are not supported. This is suitable for OpenAI file/media
uploads, not a general email MIME implementation.
