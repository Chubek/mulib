# MuLIB source-map

[Compiler integration](compiler-tools.md) · [Example](../examples/modules/source-map.c)

`add` appends a nonempty generated interval with an original byte start and source
ID. Generated intervals must be sorted and nonoverlapping; gaps are allowed.
Both generated+length and original+length must fit size_t. Mapping is one-to-one
by byte offset, not a variable-width transformation or line/column map.

`find` searches a generated byte offset and returns a one-byte entry with generated
equal to the query, original advanced by the same displacement, and source ID
preserved. Misses leave output unchanged; interval ends are exclusive.
Zero-initialize and `free` after use. Add is amortized O(1), lookup O(log entries).

## Source and build reference

[Manual index](index.md) · [Integration guide](integration.md)

| Resource | Location |
| --- | --- |
| Header | [`include/mulib-source-map.h`](../include/mulib-source-map.h) |
| Implementation switch | `MULIB_IMPL_SOURCE_MAP` |
| Repository-local includes | None |
| Complete example | [`examples/modules/source-map.c`](../examples/modules/source-map.c) |

The include list includes conditional and implementation-only includes;
it is not a minimal link recipe. Use the example (and any setup header it
includes) for a complete switch configuration. See the integration guide
for dependency placement and platform-specific linking.

Compile the example from the repository root on Linux:

```sh
cc -std=c11 -Wall -Wextra -Wpedantic -Werror -UNDEBUG -Iinclude examples/modules/source-map.c -pthread -lm -ldl -o mulib-example
```
