# On1x capability matrix

Source reviewed **2026-11-26** against MuLIB
`26c4fc0845be2ffd120ce0d68b4b7c5ee7c95be9`, bundled LibStone
`76d24a7f8b19294bab2b713dc69f799e412b62d2`, and the qualification changes
listed in the [release checklist](release-qualification.md). This is a
profile inventory, not a passing test result or a substitute for the
[linked backend registry](../backends/README.md) or
[SDK capability matrix](../sdk/CAPABILITY_MATRIX.json).

- **VERIFIED**: An exact fixture, product, target, and configuration have
  dated execution or rejection evidence. A row says explicitly if the
  evidence predates this qualification. A verified rejection is not support.
- **EXECUTABLE**: The named profile has an implemented execution path;
  this row does not claim a new qualifying run.
- **PARTIAL**: The stated capability includes a narrower implemented
  subset, an inspection-only path, or an unresolved prerequisite.
- **ABSENT**: The stated profile has no admitted path. Rejection, a design
  document, and recognition of syntax do not supply one.

The [completion ledger](../COMPLETION_MATRIX.md) indexes current evidence
and next gates. Older per-feature totals remain in the
[historical verification index](../VERIFICATION.md); do not add them to
this task's counts.

## Compiler and execution products

| Product / scope | Status | Admission, artifact, and limits |
| --- | --- | --- |
| Source and checked HIR | EXECUTABLE | Generated LibStone Aurocks or the independent fallback scanner, canonical C++ parser, explicitly authorized PPX, staging, inference and mandatory verification. Compiler is C++20; `on1x.selfhost` bootstraps native PPX tools, not the compiler. See [language](language.md) and [bootstrap](selfhosting.md). |
| Compiled scanner and parity selection | VERIFIED (focused, 2026-11-26) | W2's pinned-Aurocks generated scanner and forced fallback both passed their named Release selections; the generated selection includes scanner parity. Not whole-compiler or installation qualification. See [scanner and snapshot evidence](release-qualification.md#on1xmeta-provenance-and-snapshots). |
| `c11`: direct source to C11 | EXECUTABLE | Default reference path consumes checked HIR, not MIR. The emitter produces C source; a suitable C compiler, runtime inputs and link are separate. See [phase routes](backend-phase-audit.md). |
| `mir-text` and `mir-cfg` | EXECUTABLE | Canonical MIR text or CFG DOT, not executable code. Text supports portable directives; DOT rendering is external. Saved MIR starts at decoding and verification, not the HIR pipeline. See [wire contract](../mir/README.md). |
| `mir-eval` and `mir-c11` | EXECUTABLE | Scalar/trivial products through v1–v3; v4 attaches portable directives and must be specialized for executable consumers. `--run-ir` evaluates; `--emit-ir-c` only emits C11. See [MIR](backend-mir.md). |
| `mir-vm` / VMWeave | EXECUTABLE | In-process execution or O1VM revision 1 bytecode for `on1x-vm`. Bytecode encodes the executable MIR v1–v3 subset; v4 is specialized first. Source-only HIR projection covers bounded unmanaged records, sums, arrays, snapshot slices, and selected closures. Nominal identity is erased in this projection. No general managed values, FFI, or concurrency. See [VM](../backends/mir-vm/README.md). |
| `mir-archon` / Archon | EXECUTABLE | Opt-in, generated provider for the configured target. The measured native route is Linux AMD64 SysV: verified MIR → assembly → assembler/linker and scalar runtime → executable. SDK native dispatch requires an explicit target and its trusted adapter; the standalone tool can work with SDK disabled. No direct machine-code SDK backend or arbitrary-target qualification. See [Archon](../backends/mir-archon/README.md). |
| AMD64 Archon scalar controls | VERIFIED (scoped, 2026-11-26) | W7's exact-pin AMD64 backend-only package ran a scalar fixture and W3 separately linked and ran trusted On1x SDK assembly. Generated Release passed the native differential and the Archon project build and execution after moving the installed prefix. See [native evidence](release-qualification.md#results-and-limits). |
| Cephyr native object | EXECUTABLE | Separate opt-in checked-HIR → C11 → Linux AMD64 object route, not normal MIR lowering or a general object/link/load guarantee. An available build-host Cephyr for FFI recipe generation does not prove this in-process backend is enabled. See [Cephyr](cephyr-ffi-module-verification.md). |
| Project product selection | EXECUTABLE | On1xfile selects `c11`, `mir-c11`, `mir-vm` or `mir-archon` explicitly. Unsupported shapes, missing tools and invalid targets reject, not silently fall back. Native wrappers and installed consumers require their own checks. See [project toolchain](native-project-toolchain.md). |
| Scalar and tuple-loan backend routes | VERIFIED (historical, 2026-11-25) | Fixed source and saved-product differential across C11, evaluator, MIR-C11, VM and the configured Archon profile; canonical text, CFG, diagnostic and output-preservation controls. [Backend phase audit](backend-phase-audit.md#verified-slice) states the exact fixtures, configurations and instrumentation, not full construct coverage. |
| `on1xc --backend-capabilities` | VERIFIED (focused, 2026-11-26) | The named report test passed the first generated SDK-enabled build, and W3 independently checked the six-provider AMD64 report. The query reports linked built-ins and descriptor envelopes, not authorization, tools or executed artifacts. No plugins or direct CLI/VM routes. See [schema](../backends/BuiltinCapabilities.md) and [qualification](release-qualification.md#linked-backend-capability-reporting). |
| SDK backends and host publication | PARTIAL | Trusted built-ins use checked HIR or verified MIR according to the route. Registry membership, semantic admission, availability of build/link tools, and execution are different facts. No general plugin authority to publish checked IR or broaden a backend's supported input. See [SDK verification](../sdk/VERIFICATION.md). |
| Machine VM versus bytecode | EXECUTABLE | ArchVirt compiles and uses a freestanding DomIOS ELF on Linux AMD64 with KVM for execution; exact-image replay and native launchers are separate from VMWeave. No host fallback. Guest/image checks are not evidence that `/dev/kvm` was available. See [ArchVirt](archvirt.md). |
| `std.vmm` | PARTIAL | Pure configuration validation plus a trusted optional C companion for bounded software guests. Not a safely admitted On1x VM management API. See [stdlib VMM](../stdlib/vmm/README.md). |

## Language, ownership, and transformations

| Profile | Status | Admission and limits |
| --- | --- | --- |
| Control and scalar types | EXECUTABLE | Bounded statements, labeled/valued loops, matches, checked `i64`, bool, `f64`, unsigned fixed widths, `f32`, and numeric/boolean tuple MIR. Finite array/snapshot iteration also has an admitted VM projection. Not a general iterator, signed-narrow or pointer-width numeric, or cross-target floating conformance claim. See [core syntax](core-syntax.md), [finite iteration](finite-iteration.md), [numerics](numerics.md). |
| Nominals and aggregate data | EXECUTABLE | Bounded structural products/sums, fixed arrays, snapshots, and nominal records/enums with invariant parameters and checked matching in direct C11. Selected copy-only shapes project to VM products; that is not a general or identity-preserving MIR aggregate ABI. See [data model](data-model.md) and [nominals](nominal-adts.md). |
| Finite owners and `Result` | EXECUTABLE | Direct C11 supports checked finite `own<Named>` recursion, explicit move/take/drop, consuming nominal `Result?`, and protected cleanup. Copy-only nominal `Result` has a separate VM projection. See [owners](recursive-owning-adts.md) and [defer/errors](defer-errors.md). |
| Lexical loans | EXECUTABLE | Direct C11 handles named-place lexical loans and checked call parameters in its supported subset. MEMGraph resolves eligible scalar and copy-tuple lexical aliases to existing MIR slots; no loan opcode or runtime pointer ABI is added. No field/index loan origins, suspended loans, or general owner-payload/borrowed-parameter MIR. See [loans](core-references.md) and [backend boundaries](ownership-backends.md). |
| Explicit in-memory v5 nominal-owner APIs | VERIFIED (focused, 2026-11-26) | Single-block one-field `i64` owner, one live place, explicit create/move/drop. The named verifier, evaluator and C emitter passed scoped controls, including a handwritten C11 lifecycle oracle. Existing SDK, VM and Archon were tested for rejection, not owner execution. No source lowering or public owner wire format. See [nominal-owner evidence](release-qualification.md#nominal-owner-mir). |
| General ownership/loan and cleanup MIR, including owned `Result?` and `defer` | ABSENT | Neither direct C11 ownership checking, identity-erasing VM products nor the bounded explicit owner profile establish this support. See the [owner boundaries](release-qualification.md#nominal-owner-mir). |
| Cliches, `impl`, modules and generics | PARTIAL | Bounded coherent static generic specialization and nominal members, lexical namespaces and imported identities. [Interfaces](interfaces.md) check scoped declarations/implementations; no general functors, persisted/separately compiled ownership interfaces or dynamic dictionaries. See [cliches](core-cliche.md), [`impl`](core-impl.md), and [modules](modules.md). |
| Literals, regex, closures, metaprogramming | EXECUTABLE | Bounded text/buffer literals and interpolation, Firestone-compiled regex, immutable C11 closures, hygienic macros, authorized PPX and closed-code AOT staging. No arbitrary binary text, mutable/resource closure captures, JIT or PPX sandbox. See [literals](core-literals.md), [regex](core-regex.md), [closures](closures.md), [staging](staging.md). |
| Cooperative CSP and timer frames | EXECUTABLE | Direct C11 and private CSP ABI v5 provide fixed-size pointer-free directional channels, bounded heterogeneous poll, cancellation, process streams, deadlines and restricted stackless `launch async` timer frames. Standalone Archon timer-source projection is separate checked HIR, not async MIR. No general async functions, channel/task await, typed timeout recovery, suspended owners, native workers or actors. See [concurrency](concurrency.md), [frames](async-frames.md), and [Archon timers](../backends/mir-archon/TIMERS.md). |
| On1xMETA and MEMGraph | EXECUTABLE | Authored LLSynth processor rewrites are budgeted and rechecked. MEMGraph can remove independently proved fixed-array checks in admitted direct-C11 and VM product paths; unproved checks stay. Snapshot reproducibility is a separate release gate. See [processor semantics](processor-semantics.md) and [MEMGraph](../hir/MEMGraph/ADAPTER.md). |
| On1xMETA production snapshot and bootstrap parity | VERIFIED (focused, 2026-11-26) | Exact pinned LLSynth with validated normalized provenance; relocated samples reproduce tracked bytes, both scanner configurations build matching processor artifacts, and the processor probe passes with and without Perl discovery. Not a no-Perl whole compiler. See [snapshot evidence](release-qualification.md#on1xmeta-provenance-and-snapshots). |
| Optimization profiles, decision SSA, MIR pass and analysis coverage | PARTIAL | Implemented profile selection, bounded bool-decision SSA, transactional MIR passes and opt-in Novostone in its mapped profile. No general ownership-aware transformation or conservative-analysis result for unsupported MIR. Existing benchmark results are workload/configuration specific. See [profiles](optimization-profiles.md), [MIR passes](backend-passes.md), and [analysis](backend-analysis.md). |
| Independent Chisel/Nerotypical/Wetstone facilities | PARTIAL | Chisel and Nerotypical require their optional providers and only cover their admitted obligations. Wetstone proposals are advisory. Required but unavailable/unsupported checks reject; default builds are not evidence for enabled providers. See [safety](memory-safety.md), [type safety](type-safety.md), and [diagnostics](diagnostics.md). |

## Foreign calls, tooling, and distribution

| Profile | Status | Admission and limits |
| --- | --- | --- |
| MANIFEST, CDD and KernelBind discovery | PARTIAL | Registration and target-specific CDecl/ExoML inspection do not make a module callable. This includes FinPRED, CDD discovery and static-inline media/sandbox declarations. Historical counts only describe those snapshots. See [registration](kernel-registration.md) and [KernelBind](kernel-bind.md). |
| Build-time portable `stdffi` | EXECUTABLE | Prebuilt, validated FFISpec recipes selected with `import foreign`; bounded translated signed-`i64` operations lower without foreign calls in the emitted program. Cephyr evidence, a catalog entry, and a callable recipe are separate. See [FFIHandler](../hir/FFIHandler/README.md). |
| Rebuilt Cephyr FFISpec prerequisite | VERIFIED (scoped, 2026-11-26) | 15 focused FFISpec checks and a separate full header scan with a rebuilt host library using historical QLD parser and fresh CRTs. The full scan needed a retry; neither catalogue entries nor a successful scan grant callable FFI. The combined suite used a different, previously installed host library. See [provisioning evidence](release-qualification.md). |
| KernelBind raw or reviewed calls | PARTIAL | Exact supported raw/static profiles require lexical `unsafe`; selected static or dynamic reviewed profiles require admission for the exact target and linkage, with independent authorization where applicable. Bounded numerical, immutable C-string and framed-transport profiles have distinct contracts. No general pointer/resource/callback FFI, no production approval from a test key, and no reporting approval based on discovery. See [review](kernel-review.md), [numerics](kernel-numerics.md), [strings](ffi-strings.md) and [raw framed transport](kernel-framed.md). |
| Static PriceOpt candidate-selection fixture | VERIFIED (manual and integrated compatibility profile, 2026-11-26) | Hosted Linux AMD64 C11 with projected Exotract and test authority; exact scoring, C ABI/status and negative admission cases. Optional CTest passed with the explicit historical ExoML parser bootstrap. Not `optimize`, production review, MIR/VM or installed-FFI qualification. See [fixture evidence](release-qualification.md#native-kernelbind-fixture). |
| Load-time kernel packages | VERIFIED (historical, 2026-11-25) | The same hosted direct-C11 clamp application loaded a checked-recipe package or an explicitly trusted native package at startup in the documented Linux AMD64 configurations. Startup/rollback and native-disabled cases were separate. No general load-time FFI, MIR/VM capability, or implicit trust in an external package. See [qualification](kernel-load-qualification.md) and [package format](kernel-package.md). |
| Stdlib and On1xRT | PARTIAL | Bounded source libraries, containers, raw native companions and scoped Linux Pod fixture. On1xRT ABI 1 is distinct from both the compiler SDK and generated-program runtime; a native host callback has host-process authority. No full Basis, safe general resources, `Send`/`Sync`, or OCI/sandbox claim. See [stdlib](../stdlib/README.md) and [runtime SDK](../runtime-sdk/README.md). |
| Project lifecycle / packaging | EXECUTABLE | `on1xc aux`, scaffolding, explicit declared stdlib inputs, locked local/smart-HTTPS Git acquisition, and frozen/offline project builds. No implicit directory sweep into packages, public registry/version solver, transitive or authenticated/SSH Git acquisition. Installed and moved-prefix behavior is a separate release gate. See [On1xfile](../stdlib/on1xfile/README.md) and [search paths](search-paths.md). |
| Restricted stdlib staging fixture | VERIFIED (focused fallback, 2026-11-26) | Revised exact package inventory, empty undeclared `std.mcp` exclusion and downstream relocated-package controls passed. Not a change to source discovery or package admission. See [focused evidence](release-qualification.md#restricted-stdlib-staging). |
| Moved-prefix SDK/project consumers | VERIFIED (fallback and generated Release, 2026-11-26) | Independent install then rename outside the source tree; installed C++17/Python/CLI, exact v4 lock/negative helper, Mune and QMR ran. Generated `on1x.install` separately ran moved Archon/VM artifacts. Optional Cephyr runtime relocation not qualified. See [install and move evidence](release-qualification.md#results-and-limits). |
| Formatter, editors, diagnostics and LSP | PARTIAL | Formatter and editor highlighting are shipped. Diagnostics/scrutiny have bounded structured output; the LSP uses the compiler for parse/import diagnostics and formatting, not a typechecker-backed symbol index. No general automatic repair, recovery, completion or refactoring claim. See [formatter](formatter.md), [addons](../addons/README.md), and [diagnostics](diagnostics.md). |
| Repository-knowledge MCP | PARTIAL | Bounded read-only repository snapshot tools with provenance; no compilation or safety admission. Hosted authorization/TLS and current ChatGPT web interoperability are not established by a local run. See [addon](../addons/mcp/README.md). |
| Full compiler self-hosting, complete cross-target releases | ABSENT | Native PPX bootstrap, the fallback lexer, registered targets and test suite source do not qualify these claims. |
