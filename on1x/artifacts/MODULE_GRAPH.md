# Module graph v1 (resolved observation)

`inspect_module_graph` runs the loader's ordinary parser, resolver, access and selection checks with extension expansion and foreign admission disabled. It stops before body rewriting, checking or code generation. It does not certify execution. `LoaderOptions::capture_module_graph` optionally retains the same facts on a successful `LoadedUnit`, without a second filesystem traversal. Errors discard the builder. Inspection does not run source transforms. The C++ graph is a value; the published loaded snapshot is `shared_ptr<const ModuleGraph>`.

`grammar/{import-graph,module-dependency-graph}.schema.json` describe **successful** snapshots. Arrays of requests sort by canonical physical source ID and source order. Half-open UTF-8 byte spans and decimal offsets describe the parser's request item (e.g. `b` or `b;` in a comma-separated import), not always its enclosing statement. Alias and selector names are source spellings, never keys granting access. An ordinary selection carries an original owner/namespace/name identity. Operator IDs hash the canonical operator declaration identity. No file contents or absolute paths are emitted as display paths; literal request spellings, however, are verbatim. Fragment arrays are in manifest order. `edges` preserve distinct request witnesses even when the quotient pair is the same. Internal edges are separate. Preludes are auxiliary inputs, not computational imports. Legacy and named interface inputs carry their own digest, not executable membership.

Physical IDs use SHA-256 of the resolver's canonical path, and package IDs hash its verified canonical package origin. These are **origin-scoped** identities: relative display paths do not make moved checkouts equal. A named module without package membership is scoped to its own origin; anonymous sources carry file tags. Source digests identify revisions, never nominal type identity. Snapshot revisions hash the two canonical JSON projections (with blank snapshot ID), incorporating parsed source and interface digests, graph facts, effective membership/search inputs and OML rule digest. This is not a cache key for compiled code. Package declaration/locked revision and lockfile digest are not currently supplied by the loader API. Directory-only import providers, explicit re-export, built-in and functor identities, structured operator fixity, UTF-16 mapping, general graph decoding, and partial resolver recovery are not implemented here. Do not infer missing data or access authority from these observations.

JSON strings in the S-expression projection use JSON escaping; `(object ("key" value) ...)` and `(array ...)` distinguish empty containers. DOT is lossy. `analyze` validates references, unique request identities, unique fragment ownership and span widths. It caps nodes at 1024 and request/physical-witness counts at 16384/65536. Deterministic Kosaraju SCCs and a concrete DFS back-edge cycle witness are available even for hand-built cyclic observations; a nonempty cycle suppresses dependency-first order. Closure uses iterative traversal and excludes the queried vertex. Strict loader inspection rejects cycles. Graph deserialization confers no authority; no compiler input mode accepts this format.

Standalone evidence: `c++ -std=c++20 -fsanitize=address,undefined -Wall -Wextra -Werror -Ion1x/include on1x/tests/test_module_graph.cpp -o "$BUILD/test_module_graph"` and `python3 on1x/tests/test_module_graph_wire.py "$BUILD/test_module_graph"`. The C++ test compares both oriented closures and SCCs against independent Floyd–Warshall reachability on 500 seeded graphs, validates orders/witnesses and malformed facts. The Python test independently decodes both wire formats and compares repeated runs. `on1x/tests/test_loader.cpp` adds an overlay and legacy-edge differential fixture for full frontend builds. Full driver execution requires the missing package catalog.
