# Scalar runtime ABI qualification

## Representation and runtime mapping

`ScalarABI.c` is generated by `generate_scalar_abi.py`. Its 142 numeric
adapters accept and return `uint64_t` carriers, including for floats. They
call the actual typed functions in `runtime/on1x_runtime.c`; the compiler
performs the integer-register ↔ floating-register C ABI transition.

- `i64`: all 64 two's-complement bits, copied with `memcpy`, without an
  out-of-range unsigned-to-signed C cast.
- `u8/u16/u32/u64`: unsigned values; narrow results are zero-extended.
  Verified MIR supplies valid-width arguments. These are internal generated
  code entrypoints, not validation of arbitrary foreign carriers.
- `bool`: canonical integer zero or one.
- `f32`: binary32 bits in the low 32 bits, zero-extended on return.
- `f64`: all binary64 bits.

Compile-time checks require eight-bit bytes, LP64 pointers/`long`/`size_t`,
two's-complement `i64`, and the runtime's v1 float ABI/storage sizes.
Float adapters exist only when the real runtime declares their feature.
In particular, the runtime's unsigned↔f64 declarations are nested under its
**F32** gate, so those adapters require F32 as well. Current float qualification
is Linux AMD64/SSE2 with `FLT_EVAL_METHOD == 0`; no other float target is
qualified by these tests.

The authoritative MIR `numeric_signature` currently admits 155 names:
131 use adapters and 24 unsigned comparisons lower directly. Eleven
additional adapters serve dedicated f64 arithmetic/comparison MIR opcodes,
giving 142 adapters in total. Signed checked arithmetic uses the real
`on1x_*_i64` entrypoints with the compatible 64-bit integer calling convention.
The coverage test queries the real descriptor implementation and checks
argument/result types, rather than comparing two copied allowlists.

## Floating semantics and failures

The wrappers preserve carrier bits while delegating semantics to the runtime:

- NaNs canonicalize to `0x7fc00000` or `0x7ff8000000000000` where the
  corresponding runtime operation canonicalizes them. Negative zero survives.
- Arithmetic/comparisons/numeric conversions require SSE round-to-nearest,
  gradual underflow, and masked exceptions. Foreign rounding, FTZ, DAZ, and
  unmasked exceptions cause the runtime's exact exit-70 diagnostic.
- Bit construction/extraction, classification, signbit, and printing
  deliberately retain the runtime's environment-independent behavior.
  They do not acquire an extra MXCSR check in this adapter.
- Checked integers, unsigned conversions/shifts, and float-to-integer range
  failures retain the runtime's diagnostics, including both
  `INT64_MIN / -1` **and** `INT64_MIN % -1`.

Fast/finite-only math is rejected. Build both runtime and adapters with strict
floating options; the adapter cannot repair an independently miscompiled
runtime.

## Native function boundaries

Tuple parameters borrow flattened, contiguous eight-byte words synchronously.
A tuple result uses an explicit **first pointer argument** to caller-owned
storage and a void return. This is an internal On1x convention, not a C
by-value aggregate return. The hidden pointer counts toward the argument
budget.

The pinned generated `Backend.h` now defines `ARCHON_MIR_MAX_PARAMS=128`.
The historical 64-argument boundary remains tested. Executed tests cover:

- C→native calls with 64 and 128 integer carriers, using every argument;
- 63/127 tuple fields plus the hidden result pointer;
- C→native→native calls returning all fields through that pointer;
- nested `(u64,(f32,f64),bool)` storage with high-bit values, negative zero,
  canonical NaN, and exact word/canary checks;
- rejection of 129 scalar arguments and 128 tuple arguments plus the hidden
  result pointer, preserving existing output files;
- every numeric adapter, all 24 unsigned comparisons, and all six checked
  signed operations invoked through actual generated native functions.

Fixtures compile into several native modules to respect Archon's independent
module-symbol budget. All native generation uses the installed real backend;
the tests do not substitute a MachineIR implementation.

## Reproduce

From the repository root:

```sh
python3 on1x/backends/mir-archon/generate_scalar_abi.py --check
python3 on1x/backends/mir-archon/tests/test_scalar_abi.py \
  --cc gcc --cxx g++ \
  --build-dir /mnt/andromeda/tempdir/opencode/worker5-abi-gcc \
  --native-tool /mnt/andromeda/tempdir/opencode/on1x-archon-build/backends/mir-archon/on1x-archon-mir
```

Repeat with `--cc clang --cxx clang++` and a separate build directory.
Add `--sanitize` for ASan/UBSan (again use a separate build directory).
Omit `--native-tool` to run only the independent runtime/coverage tests.
The runner uses `-std=c11 -O2 -Wall -Wextra -Wpedantic -Werror`,
separately compiles runtime, adapters, and callers, and links the real runtime.
The descriptor query uses strict C++20. `nm` verifies absent float exports
under unqualified and f64-only feature profiles.
